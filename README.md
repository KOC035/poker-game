# ♠ ♥ ♣ ♦ 德州扑克 · 好友联机

一个纯前端的德州扑克多人对战小游戏。房主建房后把链接发给朋友，**微信里点开即可加入**，
不需要注册、不需要下载、不需要自建服务器。

---

## 🚀 怎么和朋友一起玩

1. 用 Chrome / Edge / Safari / **微信内置浏览器**打开游戏地址
   （例如 `https://<你的用户名>.github.io/poker-game/`）。
2. 所有人先在输入框填昵称。
3. **你**点「创建房间（当房主）」。
4. 复制页面上的链接（形如 `...?room=XXXXXXXX`），通过微信 / QQ 发给朋友。
5. 朋友**直接点开链接**（微信里也能直接点），填昵称后点「申请加入房间」。
6. 你在大厅看到「等待批准」，点**批准**。
7. 人齐后点「开始游戏」。

> 📱 手机端已适配，微信内可直接玩。

### 连不上时怎么办

页面底部会显示实时连接状态（`正在连接中转服务器…` / `❌ …`），
**看到红色错误提示说明问题在网络，而不是你的操作**：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 卡在「正在连接中转服务器…」很久 | 公共 MQTT broker 不可达 | 让房主换网络（手机热点常能绕过）；或按下方「自建中转」 |
| 朋友显示「房主没有响应」 | 房主页面已关，或房间号不一致 | 确认房主页面还开着；重新复制链接 |
| 显示「与房主失去联系」 | 房主的网络断了 | 让房主刷新页面重建房间，重新发链接 |
| 链接能打开但一片空白 | 直接双击本地 `index.html` 打开 | 必须通过 http(s) 访问，见「本地预览」 |

## 🌐 通信原理（这决定了为什么它在微信里也能用）

**本版已改用 MQTT 消息中继，不再使用 WebRTC 点对点。** 原因是上一版实测失败：

1. **跨网络 P2P 不可靠。** 手机 4G 与家用 WiFi 之间，运营商普遍使用 CGNAT / 对称 NAT，
   STUN 打洞会失败，表现为「连接房主超时」。
   ⚠️ 特别提醒：**在同一台电脑上开两个浏览器测试会走 host 候选直连成功，从而完全掩盖这个问题** ——
   这个陷阱我们踩过，所以现在的测试改成必须经过真实公网 broker。
2. **微信内置浏览器对 WebRTC 支持很差**（iOS 的 WKWebView / Android 的 X5 内核），
   即使 NAT 没问题，P2P 在微信里也大概率连不上。

本游戏只在两端之间传**极小的 JSON 文本**，中继转发完全够用，而且：

- 双方都是**主动外连**到 broker，不受任何 NAT / 防火墙限制
- 只依赖 **WebSocket**，所有浏览器（含微信内置）都支持
- 不需要 STUN / TURN / 信令服务器，**零成本、零部署**

### 话题设计

```text
poker/<房间号>/up               客户端 → 房主：加入请求、出牌动作、掉线通知
poker/<房间号>/down/<玩家ID>     房主 → 指定客户端：批准、拒绝、对局状态、心跳
```

房间号是 **8 位随机码**（约 8.5×10¹¹ 种组合），用来降低在公共 broker 上被猜中偷看的概率。
玩家掉线由 MQTT 的 **Last Will（遗嘱消息）** 自动通知房主，不需要额外的心跳检测。

### 自建中转（可选，想要更私密/更稳定时）

默认使用公共 broker，任何人只要知道话题名就能看到消息内容（虽然话题名很难猜）。
如果你会在意，可以自建一台 MQTT broker 并把地址加到 `BROKERS` 数组最前面：

```js
const BROKERS = [
  'wss://你的服务器:8084/mqtt',          // 自建（EMQX / Mosquitto 均支持 WebSocket）
  'wss://broker.emqx.io:8084/mqtt',      // 公共备用
];
```

```text

│   └── mqtt-lite.js    # 自研极简 MQTT 3.1.1 客户端（仅 QoS 0），13KB，纯 ES5
├── .gitignore
└── README.md
```

### 为什么自己写 MQTT 客户端

我们只需要「订阅话题 / 发消息 / 收消息」，QoS 0 足够，但现成库都有问题：

| 方案 | 问题 |
| --- | --- |
| `mqtt@5`（329KB） | 用了**可选链 `?.`、类字段 `#x`、空值合并 `??`、BigInt 字面量**等**语法级**新特性。Android 微信的 X5 老内核（Chrome 77~79）会直接抛 `SyntaxError`，**整个文件不可用** —— 与当初 CDN 挂掉是同一种故障模式 |
| `mqtt@4`（236KB） | 虽是 ES5，但实测其 `websocket-stream` 层连 `broker.emqx.io` 时**收不到 CONNACK**，必然 20 秒超时（已用调试日志 + WebSocket 拦截确认；原生 WebSocket 连同一个 URL 是通的） |
| **`mqtt-lite.js`（13KB）** | 只用 ES5 + 原生 WebSocket，任何支持 WebSocket 的浏览器（含微信内置）都能跑 |

实现覆盖 CONNECT（含 Last Will）/ CONNACK / SUBSCRIBE / SUBACK / PUBLISH / PINGREQ / PINGRESP / DISCONNECT，
处理了粘包拆包、UTF-8 编解码（带 `TextEncoder` 缺失时的回退）、心跳保活。

### 历史沿革（避免被旧文件误导）

| 阶段 | 方案 | 结局 |
| --- | --- | --- |
| 最初 | `index.html` 单文件 + WebRTC P2P，PeerJS 走 `cdn.jsdelivr.net` | 该 CDN 在部分网络不可达 → 库加载失败 → 建房毫无反应 |
| 中途 | 改用本地 PeerJS + 换可达的信令服务器 | 同机测试通过，但**跨网络 / 微信里仍然连不上** |
| 现在 | **MQTT 中继 + 自研 ES5 客户端**（本项目当前方案） | 不依赖 NAT 穿透，微信可用 |

此外，早期曾有一套 `css/` + `js/{socket,ui,main,game-logic}.js` 的四层架构实现，
但后来 `index.html` 被替换为单文件版本，那 5 个文件（约 125KB）再未被引用过，
且其中的房间 ID 前缀（`dxpk-`）与线上实现不一致 —— 照着它改代码会静默让联机失效，
因此已删除，需要时可从 git 历史（`a918015`..`ce1bf02`）找回。

## 🔒 安全与隐私说明

- **牌面不会全量下发**：房主只把「你自己」的底牌发给你，别人的底牌在摊牌前始终是 `null`，
  客户端无法直接偷看。但这套架构基于「信任房主」——**房主仍然掌握全部信息**。
- **消息经过第三方 broker**：使用默认公共 broker 时，对局消息会经过公共服务器的转发。
  在意隐私请自建中转（见上）。
- 无账号、无数据库，关闭页面即离开房间。

## ⚙️ 玩法与规则

| 项目 | 默认值 | 说明 |
| --- | --- | --- |
| 初始筹码 | 2000 | 房主可在大厅修改 |
| 盲注 | 10 / 20 | 房主可修改 |
| 座位数 | 最多 8 人 | 页面标注 `(/8)` |
| 操作 | 弃牌 / 过牌 / 跟注 / 加注 / 全下 | 加注固定为「跟注额 + 2 倍大盲」 |
| 牌型判定 | 标准 7 选 5 组合评估 | 支持同花顺到高牌，含 A2345 轮子顺 |

> **已知简化**（不影响联机，但规则上不完整）：
> 加注是固定额度，没有自定义下注滑杆；**多人全下时没有边池（side pot）处理**，
> 筹码分配不符合标准扑克规则。适合朋友间娱乐，不适合严肃对局。
