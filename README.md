# ♠ ♥ ♣ ♦ 德州扑克 · 好友联机

一个纯前端的德州扑克多人对战小游戏。房主建房后把链接发给朋友，**微信里点开即可加入**，
不需要注册、不需要下载。

> ⚠️ **请先读「第一步」**。本游戏需要一个中转服务器才能联机 —— 这是实测过三次失败方案后
> 唯一可靠的做法，部署一次约 3 分钟、免费，之后长期可用。

---

## 第一步：部署中转服务器（必做，约 3 分钟）

**为什么必须有它**：你的手机和朋友的手机之间要传牌局消息。让两台设备直接互连（P2P）
在国内网络下不可靠；用现成的免费公共服务器又实测大面积不可用（数据见下文「为什么不用现成方案」）。
自己部署一台是最稳的。

### 操作步骤

1. 打开 <https://render.com>，用 **GitHub 账号**登录（免费，不需要信用卡）。
2. 点 **New +** → 选 **Blueprint**。
3. 选择本仓库（`poker-game`）→ Render 会自动读取仓库里的 [`server/render.yaml`](server/render.yaml)。
4. 点 **Apply / Deploy**，等 2~3 分钟构建完成。
5. 部署完成后你会得到一个地址，形如：

   ```
   https://poker-relay-xxxx.onrender.com
   ```

6. **自检**：浏览器打开 `<你的地址>/health`，**看到 `ok` 就成功了**。

### 怎么用这个地址

不需要改代码。把地址拼在游戏链接后面，用 `?relay=` 参数带上即可（注意协议要写 `wss://`，路径加 `/ws`）：

```
https://<你的用户名>.github.io/poker-game/?relay=wss://poker-relay-xxxx.onrender.com/ws
```

**用这个链接创建房间**，分享出去的链接会自动把这个地址一并带上，朋友点开就能连到同一台中继。

> 💡 建议把这个带 `?relay=` 的地址存成书签，以后每次都用它开房。
> 也可以把地址直接写进 `index.html` 里的 `RELAYS` 数组（见文件内注释），那样就不必带参数了。

### 免费层的注意点

Render 免费实例**闲置约 15 分钟会休眠**，下一个人访问时需要几十秒冷启动。
页面底部会实时显示连接状态（`正在连接中转服务器…`），**等待期间不是卡死**。

## 🚀 怎么和朋友一起玩

1. 用上面那个带 `?relay=` 的地址打开游戏，所有人先填昵称。
2. **你**点「创建房间（当房主）」。
3. 复制页面上的链接，通过微信发给朋友。
4. 朋友**直接点开**（微信里也能直接点），填昵称后点「申请加入房间」。
5. 你在大厅看到「等待批准」，点**批准**。
6. 人齐后点「开始游戏」。

### 连不上时怎么办

页面底部会显示实时连接状态，**红色提示说明问题在网络，不是你的操作**：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 卡在「正在连接中转服务器…」较久 | Render 免费实例在冷启动 | 等 30~60 秒；若一直不行，先访问一次 `<你的地址>/health` 把它唤醒 |
| 朋友提示「连不上房主所在的中转通道」 | 朋友所在网络屏蔽了该地址 | 让朋友换网络（WiFi ↔ 手机流量）刷新重试 |
| 朋友提示「房主没有响应」 | 房主页面已关，或房间号不一致 | 确认房主页面还开着，重新复制链接 |
| 提示「与房主失去联系」 | 房主网络断了 | 让房主刷新重建房间、重新发链接 |
| 链接能打开但一片空白 | 直接双击本地 `index.html` 打开 | 必须通过 http(s) 访问，见「本地预览」 |

## 🧭 为什么不用现成方案（三次实测记录）

这个项目把三条路都走了一遍，结论写在下面，避免以后有人重走：

| 方案 | 结局 | 实测依据 |
| --- | --- | --- |
| **WebRTC 点对点** + PeerJS | ❌ 不可用 | 手机 4G 与家用 WiFi 之间运营商普遍用 CGNAT / 对称 NAT，STUN 打洞失败，表现为「连接房主超时」；微信内置浏览器（iOS WKWebView / Android X5）对 `RTCPeerConnection` 支持也很差 |
| **公共 MQTT broker** | ⚠️ 不可靠 | 多轮原始 CONNECT 采样：`broker.emqx.io` 2/5、`broker.hivemq.com` 0/5、`test.mosquitto.org` 0/5、`mqtt.eclipseprojects.io` 0/5，且随时间剧烈波动 |
| **自建 WebSocket 中继** | ✅ 采用 | 服务器只做同房间广播，不理解业务，几十行代码；本机与 Render 均可稳定连接 |

> ⚠️ **一个非常重要的教训**：WebRTC 版本在「同一台电脑上开两个浏览器」的测试里是 20/20 全过的 ——
> 因为同机会走 host 候选直连，**完全掩盖了跨网络的 NAT 问题**。
> 所以本项目后来的测试都强制让数据经过真实网络，而不是用 localhost 走捷径。

### 公共 broker 仍然保留作兜底

`index.html` 里的 `BROKERS` 数组仍保留公共 broker 作为最后兜底：房主会**并行竞速**所有通道
（自建中继优先），取最先连上的那条，并把通道编号写进分享链接（`&t=r0` 表示中继 0 号），
确保双方在同一条通道上。全部失败会整体重试 3 轮，以容忍公共服务抖动。

## 💻 本地预览

**必须通过 HTTP 访问**，直接双击 `index.html` 不行：

```bash
cd poker-game
python -m http.server 8000
# 浏览器打开 http://localhost:8000
```

想本机对测，可以顺便把中继也跑起来：

```bash
cd poker-game/server
npm install
npm start          # 中继监听 8080
```

然后两个人分别用这个地址打开（用两个不同浏览器或无痕窗口）：

```
http://localhost:8000/?relay=ws://127.0.0.1:8080/ws
```

## 📁 目录结构

```text
poker-game/
├── index.html          # 全部页面结构 + 样式 + 游戏逻辑 + 网络层（单文件实现）
├── vendor/
│   └── mqtt-lite.js    # 自研极简 MQTT 3.1.1 客户端（仅 QoS 0），13KB，纯 ES5
├── server/             # 中转服务器（部署用，见「第一步」）
│   ├── relay.js        #   极简 WebSocket 中继：只做同房间广播，不理解业务
│   ├── package.json
│   └── render.yaml     #   Render 一键部署配置
├── .gitignore
└── README.md
```

### 关于 `vendor/mqtt-lite.js`

这是给「公共 MQTT broker 兜底」用的最小客户端。之所以自己写而不是用现成库：

| 方案 | 问题 |
| --- | --- |
| `mqtt@5`（329KB） | 用了可选链 `?.`、类字段 `#x`、空值合并 `??`、BigInt 字面量等**语法级**新特性。Android 微信的 X5 老内核（Chrome 77~79）会直接抛 `SyntaxError`，**整个文件不可用** —— 与「CDN 被拦截导致建房无反应」是同一种故障模式 |
| `mqtt@4`（236KB） | 虽是 ES5，但实测其 `websocket-stream` 层连公共 broker 时收不到 CONNACK，必然超时（已用调试日志 + WebSocket 字节拦截确认：CONNECT 报文完全符合规范，但服务器无响应） |
| **`mqtt-lite.js`（13KB）** | 只用 ES5 + 原生 WebSocket，任何支持 WebSocket 的浏览器（含微信内置）都能跑 |

覆盖 CONNECT（含 Last Will）/ CONNACK / SUBSCRIBE / SUBACK / PUBLISH / PINGREQ / PINGRESP / DISCONNECT，
处理了粘包拆包、UTF-8 编解码（`TextEncoder` 缺失时回退）、心跳保活。

### 历史清理记录

早期曾有一套 `css/` + `js/{socket,ui,main,game-logic}.js` 的四层架构实现，但后来 `index.html`
被替换为单文件版本，那 5 个文件（约 125KB）再未被引用过，且其中房间 ID 前缀（`dxpk-`）

## 🔒 安全与隐私说明

- **牌面不会全量下发**：房主只把「你自己」的底牌发给你，别人的底牌在摊牌前始终是 `null`，
  客户端无法直接偷看。但这套架构基于「信任房主」——**房主仍然掌握全部信息**。
- **自建中继时消息只经过你自己的服务器**，不经过任何第三方。
- 公共 MQTT 兜底通道的话题是公开的（房间号为 8 位随机码，约 8.5×10¹¹ 组合，不易被猜中），
  介意隐私请使用自建中继。
- 无账号、无数据库，关闭页面即离开房间。

## ⚙️ 玩法与规则

| 项目 | 默认值 | 说明 |
| --- | --- | --- |
| 初始筹码 | 2000 | 房主可在大厅修改（改动后点「应用设置」） |
| 盲注 | 10 / 20 | 房主可修改；锦标赛模式下每 10 手翻倍 |
| 座位数 | 最多 8 人 | 满员后新申请会被自动拒绝 |
| 操作 | 弃牌 / 过牌 / 跟注 / 加注 / 全下 | 加注用滑杆自选额度，最小加注额自动限制 |
| 连续对局 | 支持 | 结算后可点「下一局」，庄家按钮自动轮转 |
| 牌型判定 | 标准 7 选 5 组合评估 | 支持同花顺到高牌，含 A2345 轮子顺 |

### 已实现的规则细节

- **分池（side pot）**：多人以不同筹码量全下时，按投入分层建池分别比牌，
  筹码不会凭空消失或分配错位。
- **平局平分**：牌力完全相同时底池均分，余数依次分给先手。
- **提前结束**：翻牌前全体弃牌时，唯一未弃牌者直接收下全部底池。
- **最小加注**：加注到低于「最大注 + 大盲」会被自动抬到该值；筹码不足时退化为跟注或全下。
- **全下跟注**：筹码不够跟注时按全下处理，不影响后续街的继续进行。
- **防作弊**：别人的底牌在摊牌前始终是 `null`，客户端拿不到。
- **补码**：积分赛模式下输光可申请补码（下一局生效）。

### 仍属简化（娱乐向，不适合严肃对局）

- 没有盲注计时器、没有自动弃牌（不代表超时会自动过牌/弃牌）
- 补码固定回到初始筹码，不支持自定义金额
- 没有牌局历史 / 战绩统计
- 房主是唯一裁判，架构基于「信任房主」

## 🔄 更新记录

### 2026-10 整体优化

修复了 6 个实际影响可玩性的缺陷（均配了回归测试）：

1. **发牌会重复** —— 每次推进公共牌都 `makeDeck()` 重建牌堆，同一张牌可能发两次。
   改为整局共用一副牌。
2. **房主设置完全不生效** —— 筹码/盲注/模式这几个输入框从未被 JS 读取。
   现在开局读取，并新增「应用设置」按钮。
3. **只能玩一局** —— 结算后没有任何入口继续，游戏直接卡死。
   新增结算面板与「下一局」，庄家按钮轮转。
4. **底池在提前结束时蒸发** —— 翻牌前全体弃牌时，`getHandScore` 只有 2 张牌、
   凑不出 5 张组合而返回 `null`，导致无人被判定获胜、筹码消失。
   现在唯一幸存者直接收下全部底池。
5. **平局不平分** —— 同牌力时先遍历到的人独吞底池。改为均分（余数给先手）。
6. **没有分池** —— 多人不同筹码量全下时分配错误。按投入分层建池。

另外：加注改为滑杆自选额度、修复迷你牌样式缺失、昵称 HTML 转义（防 XSS）、
`alert` 换成页内提示、复制链接改用 Clipboard API、强制 8 人上限、昵称去重、
锦标赛盲注递增、补码功能。
