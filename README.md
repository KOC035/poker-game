# ♠ ♥ ♣ ♦ 德州扑克 · 好友联机

一个纯前端的德州扑克多人对战小游戏。房主建房后把链接发给朋友，朋友点开即可加入，
**不需要注册、不需要后端账号、不需要下载**。

通信走 WebRTC 点对点（P2P）：牌局状态由房主的浏览器维护，其他玩家直连房主，
只有建立连接时的信令需要一台服务器中转。

---

## 🚀 怎么和朋友一起玩

1. 用 Chrome / Edge / Safari 打开游戏地址（例如 `https://<你的用户名>.github.io/poker-game/`）。
2. 所有人先在输入框填昵称。
3. **你**点「创建房间（当房主）」。
4. 复制页面上的链接（形如 `...?room=XXXXX`），通过微信 / QQ 发给朋友。
5. 朋友点开链接 → 点「申请加入房间」。
6. 你在大厅看到「等待批准」，点**批准**。
7. 人齐后点「开始游戏」。

> 📱 手机上也能玩，建议横屏或直接用微信内置浏览器打开。

### 连不上时怎么办

页面底部会显示实时连接状态（`正在连接信令服务器…` / `❌ …`），
**看到红色错误提示说明问题出在网络而不是操作**：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 点「创建房间」一直没反应，状态栏长时间停在「正在连接信令服务器…」 | 信令服务器不可达 | 换一台信令服务器（见下）；或让房主换网络（手机热点常能绕过） |
| 朋友点链接后提示「找不到房间」 | 房主页面已关闭，或房间号输错 | 确认房主页面还开着；重新复制链接 |
| 提示「连接房主超时」 | 双方网络 NAT 类型不兼容 | 让房主改用手机热点，或按下方说明加一台 TURN 服务器 |
| 链接能打开但一片空白 | 直接双击本地 `index.html` 打开（浏览器拦截了本地脚本） | 必须通过 http(s) 访问，见「本地预览」 |

## 🌐 关于信令服务器（重要）

WebRTC 建立连接前，双方需要交换一次握手信息，这一步由**信令服务器**完成。
本项目历史上默认使用 PeerJS 官方公共服务器 `0.peerjs.com`，但实测在部分网络环境下
**TCP 能连上、TLS/WSS 握手却会被中途重置（SNI 阻断）**，表现就是「建房完全没反应」。

现在 `index.html` 顶部的 `SIGNALING_SERVERS` 数组按顺序回退，当前为：

```js
const SIGNALING_SERVERS = [
  { host: 'peerjs-server.onrender.com', port: 443, path: '/', secure: true }, // 实测可达
  { host: '0.peerjs.com',               port: 443, path: '/', secure: true }, // 官方，异地网络备用
];
```

⚠️ 第一台是**第三方公共实例**，不受我们控制、免费层会休眠（首次连接可能要等几十秒）。
**想要长期稳定，请自建** —— 仓库 [`server/`](server/) 目录已备好可直接部署的服务：

### 自建信令服务器（约 3 分钟）

1. 打开 <https://render.com> 注册（可用 GitHub 账号直接登录）。
2. 点 **New + → Blueprint**，选择本仓库，Render 会自动读取 [`server/render.yaml`](server/render.yaml)。
3. 等部署完成，得到形如 `https://poker-signaling-xxxx.onrender.com` 的地址。
4. 自检：浏览器打开 `<你的地址>/peerjs/id`，**返回一串 UUID 就说明服务正常**。
5. 把该地址填到 `index.html` 的 `SIGNALING_SERVERS` **最前面**：

```js
const SIGNALING_SERVERS = [
  { host: 'poker-signaling-xxxx.onrender.com', port: 443, path: '/', secure: true },
  { host: 'peerjs-server.onrender.com',        port: 443, path: '/', secure: true },
];
```

6. 提交推送，下次所有人打开页面就会走你自己的服务器。

### 遇到对称 NAT 打不通时

本项目当前依赖 STUN 打洞，已实测本机 NAT 为「锥形（端口无关映射）」，可正常打通。
如果将来换到严格对称 NAT 的网络（部分移动网络、公司网络）连不上，需要加一台 TURN 中继：

```js
const ICE_SERVERS = [
  { urls: 'stun:stun.miwifi.com:3478' },
  // 追加你的 TURN（可用 coturn 自建，或付费 TURN 服务）
  { urls: 'turn:你的服务器:3478', username: '用户名', credential: '密码' },
];
```

## 💻 本地预览

因为使用了 ES 模块之外的外部脚本与 P2P，**必须通过 HTTP 访问**，直接双击 `index.html` 不行：

```bash
cd poker-game
python -m http.server 8000
# 浏览器打开 http://localhost:8000
```

想两个人本机对测，开两个**不同的浏览器**（或一个正常窗口 + 一个无痕窗口）分别打开上面的地址。

## 📁 目录结构

```text
poker-game/
├── index.html            # 全部页面结构 + 样式 + 游戏逻辑 + 网络层（单文件实现）
├── vendor/
│   └── peerjs.min.js     # PeerJS 1.5.4，本地自带（原实现走 CDN，被拦截后整个游戏无法使用）
├── server/               # 可选：自建信令服务器（部署后把地址填回 index.html）
│   ├── server.js
│   ├── package.json
│   └── render.yaml       # Render 一键部署配置
├── .gitignore
└── README.md
```

> **关于历史上的 `css/` 与 `js/` 目录**：早期版本曾重构为 `socket / game-logic / ui / main`
> 四层架构，但后来 `index.html` 被替换为单文件版本，那 5 个文件（约 125KB）再也没有被引用过，
> 且其中的房间 ID 前缀（`dxpk-`）与线上实现（`poker-host-`）不一致 —— 一旦有人照着它改代码，
> 会静默地让联机失效。因此已删除，需要时可从 git 历史（commit `a918015`..`ce1bf02`）找回。

## 🔒 安全与隐私说明

- **牌面不会全量下发**：房主只把「你自己」的底牌发给你，别人的底牌在摊牌前始终是 `null`，
  因此客户端无法直接偷看。但请注意，**房主仍然掌握全部信息**，这套架构基于「信任房主」。
- **信令内容经过第三方服务器**：若使用公共实例，握手信息（含内网 IP）会经过他人服务器。
  在意隐私请自建信令服务器。
- 无账号、无数据库，关闭页面即离开房间。

## ⚙️ 玩法与规则

| 项目 | 默认值 | 说明 |
| --- | --- | --- |
| 初始筹码 | 2000 | 房主可在大厅修改 |
| 盲注 | 10 / 20 | 房主可修改 |
| 座位数 | 最多 8 人 | 页面标注 `(/8)` |
| 操作 | 弃牌 / 过牌 / 跟注 / 加注 / 全下 | 加注固定为「跟注额 + 2 倍大盲」 |
| 牌型判定 | 标准 7 选 5 组合评估 | 支持同花顺到高牌，含 A2345 轮子顺 |

> 加注目前是固定额度（`大盲 × 2`），没有自定义下注滑杆，也没有边池（side pot）处理 ——
> 多人全下时筹码分配不符合标准规则。这属于已知的简化，适合朋友间娱乐。
